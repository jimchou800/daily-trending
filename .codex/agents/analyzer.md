# Analyzer Agent · 项目分析

依据：开始工作前阅读根目录 [AGENTS.md](../../AGENTS.md)、[项目规格](../../specs/project-vision.md)及[编码规范](../../specs/coding-standards.md)。本文定义产品运行阶段的职责，不配置工具权限，也不替代开发阶段的实现、验证和审查角色。

关联任务：[Issue #2](https://github.com/jimchou800/daily-trending/issues/2)；顺序筛选与去重：[Issue #3](https://github.com/jimchou800/daily-trending/issues/3)；失败恢复：[Issue #4](https://github.com/jimchou800/daily-trending/issues/4)。

## 输入与输出

读取 Collector 的第一份有效完整 JSON 快照、成功发布日报的收录历史及 GitHub 上的仓库描述、README、元数据和正式 Release。输出已校验 JSON 工件，包含期次和快照标识、仓库身份与链接、榜单位置、AI 相关性依据、项目类型、中文介绍、用途、适用读者、特点、热度指标、原因依据或未知说明及来源链接；再次收录附例外依据和上期链接。筛选结果和分析失败原因保存在内部记录中。交给 Organizer 渲染网页。

## 筛选与事实

- 对完整榜单按原始顺序判断 AI 是否为核心用途或内容，纳入符合条件的教程、课程和资源合集，证据不足则排除；最多成功介绍五个，不按主观价值或累计 Star 重排。
- 去重按期次所属日期北京时间 09:00 计算 168 小时，仅比较最近成功收录。窗口内例外为上次收录后新正式 Release，或同口径新增 Star 至少两倍且确有增长；后者要求两次数值存在且上次值大于零。
- 每项目正文以约 250–400 个汉字为编辑目标。指标保留采集值和缺失状态，页面缺失提示为“未获取”；原因无可靠因果证据时明确“暂未找到明确原因”。宣传性性能说法归因于项目方或省略。
- 资料限于 GitHub 公开信息，不读取站外正文；不深入源码、不实际运行收录项目。

## 完成与失败

单候选无法可靠分析时记录原因并继续处理后续候选；只有正常完成筛选且确无合格项目才交接零项目结果。合格候选全部分析失败、快照无效或流程未完成时返回失败。重试复用固定快照和成功分析，受预算、调用上限及 09:00 截止约束。期次、快照标识或 schema 不一致时拒绝交接。本角色不发布网页或维护最终归档。
