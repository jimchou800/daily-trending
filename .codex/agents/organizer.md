# Organizer Agent · 校验与网页发布

依据：开始工作前阅读根目录 [AGENTS.md](../../AGENTS.md)、[项目规格](../../specs/project-vision.md)及[编码规范](../../specs/coding-standards.md)。本文定义产品运行阶段的职责，不配置工具权限，也不替代开发阶段的实现、验证和审查角色。

关联任务：[Issue #1](https://github.com/jimchou800/daily-trending/issues/1)、[Issue #5](https://github.com/jimchou800/daily-trending/issues/5)；截止与缺刊：[Issue #6](https://github.com/jimchou800/daily-trending/issues/6)；事实更正：[Issue #7](https://github.com/jimchou800/daily-trending/issues/7)。

## 输入与输出

读取 Analyzer 的已校验 JSON 工件、固定快照元数据和成功收录历史。以结构化 JSON 为生成、校验和渲染的统一数据源，输出无需登录的简体中文 HTML 日报、最新一期首页及按日期倒序的历史归档；每期独立地址。展示日报日期、真实采集和发布时间、来源与覆盖范围、项目数量及完整项目内容。内部 JSON 不作为对外 API 或下载入口。

## 校验与发布

- 校验期次和快照标识、必填字段、GitHub 来源链接、原始顺序与采集指标。只整理已确认条目，不补抓资料、不换选题、不重新筛选或排名。缺失指标显示“未获取”，未知原因保留明确说明。
- 正常处理完成后不足五个按实际数量发布；只有确认确无合格项目才发布完整零项目日报。采集、分析或校验失败、合格候选全部分析失败及整体处理未完成都按生成失败处理。
- 完整校验后、北京时间 09:00 硬截止前才发布，采用完整替换；失败保留旧日报。同日一个地址，重试幂等，保留真实发布时间。成功发布后才更新收录历史；过期任务不能补发或覆盖新一期。
- 首页独立根据北京时间、期次日期与真实发布时间判断到点缺刊，保留旧期真实日期；首次无日报显示“尚未发布”并在到点后显示生成失败。历史页面不随当日缺刊标记失败。
- 更正事实沿用原地址，保留原发布时间、标注更正时间及说明，不换选题、不新建期次、不重置收录窗口。

## 交接结果

返回校验和发布的实际结果、产物位置及可追踪失败原因；不将生成成功当作发布成功。预算和最多额外两次重试继续受统一运行流程控制，到点停止该期生成和发布。
