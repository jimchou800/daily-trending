# Hosted publication authority

The Python generator uses a Cloudflare Worker and one stable named SQLite Durable Object as the authoritative private ledger and public HTML origin. The Worker does not execute models, fetch news, provide a public data API, accept public generation requests, or introduce reader accounts. `worker/` is a separate, strictly typed TypeScript toolchain; Python gates remain separate.

## Local verification

From `worker/`, run `npm ci` followed by `npm run check`. This runs strict TypeScript checking (including tests/config), ESLint common-error/unused checks, comment-only pending-work scanning, test exclusion/skip guards, formatting and all real workerd tests with Istanbul instrumentation. Empty suites fail. Coverage includes every `src/**/*.ts` file, excludes declaration files, and requires lines, branches, functions and statements independently >=80%. Reports: `worker/coverage/coverage-final.json` and `worker/coverage/index.html`. Business transactions are real SQLite transactions in the Workers test runtime. Tests substitute only the clock and persistence synchronization boundary to exercise cutoff failures; SQL storage, selection validation, rendered pages and pointer/history writes execute normally.

On Windows, use a short temporary directory and worktree path if workerd cannot open SQLite paths: e.g. `$env:TEMP='D:/codex/cache/hosted-runtime'; $env:TMP='D:/codex/cache/hosted-runtime'` after creating that directory. The test config uses a single Worker and explicitly clears real storage before each test, because stacked SQLite isolation can encounter Windows file locking. Miniflare may emit cleanup `EBUSY` warnings after successful tests; these warnings do not prove remote deployment behavior. Linux CI uses normal temporary paths.

The same check also executes the exact public browser script in Node VM scenarios with controlled DOM and browser clocks, then repeats those scenarios with Istanbul instrumentation of the emitted script body. This separately enforces >=80% lines and branches for code embedded as text, with auditable JSON/HTML under `worker/coverage/browser/`; importing a string alone does not establish browser-code coverage. Scenarios cover the 09:00 edge, on-time versus late/missing publication metadata, day/month rollover, periodic refresh, focus, visibility resume and back-forward restoration. These controlled tests do not establish live browser/network timing acceptance.

## Public homepage status

The homepage includes a same-origin static `/home-status.js` resource allowed by CSP `script-src 'self'`. Both HTML and script use `Cache-Control: no-store`. Server rendering and browser clock checks use the visible latest issue's date and original publication time to determine missing issues; no generation-task failure record is required. The browser reevaluates at Beijing 09:00 and midnight, refreshes the existing HTML route at most a minute apart to obtain newly published content, and reevaluates on focus, visibility resume or back-forward restoration. Archive pages do not load this script or show current-day/month generation status. No public JSON or status API is added.

A rejected reservation whose conservative cost would exceed the monthly cap durably records `generation_exhausted` on that month. Only that recorded condition shows the homepage's “当月生成额度已用尽” hint; accounting uncertainty/pending usage alone does not imply exhaustion. Existing reservations, billing bounds and admission checks are unchanged. The next month's homepage does not inherit this hint, and public reads remain available despite exhausted or accounting-blocked generation budgets.

The hosted runner also handles monetary rejections by the Python client's earlier local guard: it sends authenticated `budget-notice` with the pending input/output token estimates and configured monthly limit, before the unchanged local guard stops the call. The Worker bounds those token estimates exactly as for reservations, recomputes the tariff, and latches only when its own durable month total plus that estimate exceeds the configured limit (at most CNY30). The notice neither creates a reservation nor changes spend or grants dispatch. Accounting/pending failures and per-run call limits do not send a monetary notice; an affordable or stale caller estimate cannot establish exhaustion on its own.

`worker/wrangler.json` declares `new_sqlite_classes` and the `PUBLICATION_AUTHORITY` binding. Do not change the namespace identity or pinned `PUBLICATION_OBJECT_NAME` across deployments. ## Private protocol

Every automation request requires `Authorization: Bearer <PUBLICATION_AUTOMATION_TOKEN>` and `X-Installation-ID: <PUBLICATION_INSTALLATION_ID>`. JSON objects are validated from `unknown`. Responses use JSON; errors are `{ "error": "code" }`, with 400 invalid input, 401 unauthorized, 403 disabled bootstrap, 404 unknown route, 405 wrong method, 409 deadline/fence/admission conflict, 413 artifact limits, and 503 unavailable authority. Automation responses contain private information and must not be exposed by another public proxy.

| Method/path under `/_automation/` | Request | Response/behavior |
| --- | --- | --- |
| POST `install` | `bootstrap_token` | `{installed:true}`, explicit one-time new installation |
| POST `begin` | `period`, `run_id` | `{period,run_id,fence,attempts}`; same run id idempotent, at most three distinct attempts total per date |
| POST `budget-notice` | `period`, `fence`, `input_tokens`, `output_tokens`, `limit_micros` | `{generation_exhausted}`; validate durable monetary shortage without reserving, billing or dispatching |
| GET `state?period=D` | no body | `{period,attempts,fence,artifacts,reservations,month,history,publication}`; history contains original successful inclusion reports; publication is current corrected report or null |
| POST `reserve` | `period,fence,key,amount_micros,input_tokens,output_tokens` | `{dispatch,reservation}`; first response permits one transport, duplicate returns `dispatch:false` |
| POST `usage` | `period,key,actual_micros,usage_status?,accounting_blocked?` | `{accounting_blocked}`; same amount/status idempotent, conflicting re-accounting rejected; allowed after deadline/stale fence |
| PUT `artifact` | `period,fence,key,value` | `{stored:true}`; every key immutable, identical retry accepted, conflicting retry rejected |
| POST `stage` | `period,fence,report` | `{hash}`; immutable validated JSON blob remains private |
| POST `publish` | `period,fence,hash` | `{report,url,idempotent}`; server stamps canonical `published_at`; same date returns canonical publication without replacing selections |
| POST `correct` | `period,report,correction_note` | same publication envelope; requires existing date, same selected repositories, original `published_at`; adds `corrected_at` and note, no new inclusion event |

`period` is an ISO date. Fences are increasing integers. New generation/payment/storage/publication requests must be for the server's current Beijing date and before 09:00. Paid requests reserve first and await durable synchronization before permission to dispatch. `amount_micros` uses integer micro-CNY (CNY1 = 1,000,000). The Beijing-region approved tariff lower bound is 12 micro-CNY/input token and 36 micro-CNY/output token; the authority rejects reservations below `input_tokens*12+output_tokens*36`. The Python adapter derives its conservative input bound from UTF-8 bytes plus256 overhead and output bound from cap plus10 tokens. These are deliberately conservative assumptions that must be revalidated when model/prompt/provider framing changes. This authority does not itself send model requests or verify provider invoices.

Input cap32,000, output cap8,000, at most40 paid transport attempts/date and shared Beijing natural-month reserved spend <=30,000,000 micro-CNY. Model IDs are qualified `dashscope/qwen3.8-max` internally and `qwen3.8-max` at the remote transport; region/tariff changes require a reviewed code change. Other runtime service costs must fit the same CNY30 total budget: selected free hosting is assumed CNY0 only within verified Free quotas. Reservation is never refunded for unknown or lower actual usage. Lost reserve acknowledgements must be queried through state and never redispatched. Each paid retry needs a new key. An unresolved reservation blocks every further paid admission in that month until usage is recorded. Provider transport exceptions are settled with `usage_status:unavailable` and the full reservation as the conservative charge in `actual_micros`; the authority rejects smaller unknown charges. A confirmed settlement permits a separately charged retry within existing limits. Returned valid usage is `reported` (the backward-compatible default); invalid returned usage sets `accounting_blocked:true`, and underestimated actual adds the difference and blocks the month. Lost settlement acknowledgements stop further dispatch. That state survives runner restarts; public reads do not consult model budget.

Required artifact `snapshot` is `{complete:true,source:"https://github.com/trending?since=daily",collected_at,entries:[{rank,repository,repository_url,stars_today,stars_total,...}]}`. It is the first valid complete snapshot, ordered contiguous ranks, unique repositories, null missing metrics and a same-date actual collection timestamp. Preserve the original collector artifact separately for cache recovery. Other pipeline/cache artifact keys may contain schema/model/prompt identity, but are immutable as well.

Required artifact `selection` is `{completed:true,eligible_count,decisions:[{repository,is_ai,ai_relevance_evidence,outcome,releases?}]}`. Decisions cover every snapshot entry in order. Outcomes are `selected`, `excluded` or `analysis_failed`. `eligible_count` equals selected plus analysis_failed; selected repositories exactly match the report sequence. Positive eligibility with zero successes is generation failure. Optional formal release evidence is `{draft:false,prerelease:false,published_at,html_url}`. The authority independently checks selected report metrics/order, GitHub HTTPS links, required fields, reason evidence, original successful history, 168-hour windows, positive-base Star doubling and formal release timing. AI relevance and factual prose still depend on the constrained analyzer/source verification; structural validation is not independent proof of prose truth.

Report JSON follows the existing contract1.0. `status:sample_preview,published_at:null` is accepted at staging. Public rendering uses only explicit reader fields from validated JSON, escapes text and links, and never embeds arbitrary submitted HTML/private trace fields. Public routes are GET `/`, `/archive/` and `/archive/YYYY-MM-DD/` (also `index.html`); there is no public JSON, raw blob or artifact route. The homepage independently derives missing-today failure using server Beijing time and canonical publication date/time; historical pages do not inherit that banner. Mutable pages use `Cache-Control:no-store` and a restrictive CSP.

## Publication transaction and deadline limitation

Publication runs inside `blockConcurrencyWhile`, including all persistence waits. The immutable JSON blob is written first. A durable rollback intent records the prior head/date/inclusion state. The issue revision pointer, original successful inclusion report and latest pointer change in one SQLite transaction. After `storage.sync()` returns, the authority checks the server deadline and records a hash-bound confirmation receipt containing that observation time. The rollback intent and receipt remain together until the next request reconciles them; publication never erases its recovery evidence before returning. A crossed cutoff observed after either synchronization rolls back and synchronizes the previous state.

Every request reconciles a surviving intent before public reads or private state access. Only a receipt matching the current issue hash, with a finite nonfuture observation time, can retain the candidate. A normal publication receipt must be observed on its own Beijing date strictly before09:00. Missing, mismatched, late or wrong-date receipts roll back. Maintenance receipts retain the explicit same-date exception; factual corrections may legitimately be confirmed on a later date. Restart does not create a new publication, regenerate content or advance inclusion history. Existing already-published records without an outstanding journal remain compatible.

For a new issue, `published_at` is the server time observed after content and initial pointers have completed durable synchronization. The immutable blob retains its preliminary internal timestamp; canonical responses and public rendering overlay the authoritative issue metadata, and successful inclusion history stores the same observed timestamp. Corrections and replay preserve it. This records observed durable content completion rather than the start of upload. Metadata and its receipt are then synchronized together before success.

The server stops admitting new publications five seconds before09:00 as an operational safety margin. The product deadline remains09:00. This margin is not an upper latency guarantee. Cloudflare provides no clock-conditional durable COMMIT or exact commit timestamp, and Workers clocks advance only after I/O. The receipt establishes that the candidate content and initial pointers were observed durable before cutoff; it cannot establish the physical durability time of the later receipt itself, first public network visibility, or response delivery. A crash after receipt persistence but before the final clock check can recover only that already-confirmed content, never an unconfirmed candidate. Local persistence-boundary tests establish the recovery rule, not an exact physical visibility guarantee. Real scheduling, latency and platform behavior remain operational observations; this protocol does not relax the09:00 admission or observed-cutoff rollback rules.

Report blobs are <=512KiB, cumulative admitted artifacts/blobs <=2MiB/date, and tracked payload growth stops at800MiB (headroom below the stricter1GiB Free per-object bound). No automatic archive deletion occurs. This counter includes stored JSON payload growth, not SQLite/index overhead; monitor real storage/row/CPU/request usage and stop earlier if needed. Free quota exhaustion may affect old-page availability; this is not established by retaining bytes. Do not claim unlimited archiving or daily model-budget feasibility solely from existence of free quotas.
