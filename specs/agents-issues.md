### 与现行规格对齐

- collector → analyzer → organizer 为逻辑阶段，不承诺三个独立模型、服务或运行实例。collector 采集完整 Daily 全语言榜；analyzer 进行 AI 判断、顺序筛选和可靠分析；organizer 校验并生成静态网页。
- UTC 0:00 等于北京时间 08:00，只能作为待验证的启动候选；以北京时间 09:00 发布硬截止点反推启动安排，不预设平台能保证准点。
- PRD 的“三维标签”没有定义，不自行发明标签体系；改为规格要求的相关性依据、项目类型和正文等结构字段。
- PRD 的 MD 产物按现行规格改为 JSON 数据源与公共静态网页，不增加 Markdown 下载或对外 API。
- 当前目录未发现应用代码，也不是 Git 仓库；用户已指定远端 git@github.com:jimchou800/daily-trending.git，使用 GitHub Issues 与 feature 标签。不虚构父 issue 或 issue 链接。

## I1 · 用保存样本贯通三阶段，生成可阅读的一期日报

User stories covered：US-1、US-3、US-4。依据：规格 §4、§6，编码规范 CS-01–CS-15。

### What to build

建立最薄的 collector → analyzer → organizer 串行链路，以保存的完整榜单和模型响应样本完成解析、判断、分析结果校验及静态页面生成。定义三个阶段交接的 JSON 契约与内部状态，让后续真实采集和模型调用能替换外部边界。选择实际所需语言、工具链并建立相应 CI 质量门槛。

### Acceptance criteria

- [ ] 一组来源受控的保存样本可贯通真实内部逻辑，生成一期可在手机和桌面阅读的简体中文页面；样本仅用于开发验证，不作为线上当日日报。
- [ ] 期次 JSON 覆盖日期、时区、采集时间、发布时间、来源、统计口径、运行状态及条目；条目覆盖规格要求的身份、原始位置、相关性、类型、正文、热度、原因依据及来源等字段。预发布状态不伪造实际发布时间。
- [ ] 内部工件记录期次标识、快照标识、阶段状态和错误；下游拒收 schema 不符、错期次、错快照及未完成的上游工件。
- [ ] 页面展示仓库链接、覆盖范围、数量、各项热度的口径；缺失指标为“未获取”，未知原因明确显示“暂未找到明确原因”。
- [ ] 落实共同质量条件；提供可运行的实际命令、CI 报告与分支保护结果，不把样本流程通过等同于上线完成。

### Blocked by

None - can start immediately。

## I2 · 从完整实时榜单生成可信日报，并限制模型费用

User stories covered：US-1、US-2、US-4。依据：规格 §2–§4、§6–§7。

### What to build

把外部替身接成真实 GitHub 采集与受限模型调用，输出可校验、可阅读的候选日报预览。先核实实际服务定价与调用预算再接付费调用；本切片不向公众发布。

### Acceptance criteria

- [ ] 只从 Daily 全语言榜获取成功返回的全部仓库，保留顺序、真实采集时间与指标，不假定条数、不预截前 5 个、不补榜外项目。完整性校验失败不形成有效快照。
- [ ] 仅使用 GitHub README、元数据、正式 Release 等公开资料判断 AI 核心相关性并留依据；支持教程、课程和合集，证据不足排除，不访问外链正文。
- [ ] 按源顺序产生最多 5 个可靠分析条目；单候选失败记录原因并继续后续候选，正常不足 5 个按实际数量生成。
- [ ] 每条正文以约 250–400 汉字为编辑目标，覆盖用途、适用读者及有来源的特点；不编造因果，近期动态与走红原因分开，宣传性效果归因项目方或省略。
- [ ] 校验必填字段、GitHub 链接来源及数值与快照一致性，模型无法覆盖采集指标；拒绝不可追溯的主要事实，不以链接字段存在代替事实抽查。
- [ ] 区分真正无合格候选、部分分析成功、合格候选全部分析失败、抓取失败和整体未完成；仅第一种可形成带筛选说明的零项目日报。
- [ ] 核实模型、调度、托管及其他日常服务的价格与限额，包含汇率、全部候选相关性判断和保守重试费用，给出每月不超过人民币 30 元的容量测算。
- [ ] 限制输入、输出、调用次数及重试；每次付费调用前预留保守费用，无法确定既有调用费用时不重复释放额度。记录实际或保守估算消耗，并验证额度不足停止调用、下月恢复。
- [ ] 保存真实试运行的来源与成本证据；按共同质量条件验证完整榜单、顺序、事实来源、缺失数值和失败分类边界。

## I3 · 根据成功收录历史筛选本期，并说明再次入选变化

User stories covered：US-1、US-3。依据：规格 §3、§6。

### What to build

从历史成功日报读取最近一次收录记录，贯通顺序筛选、去重、内容生成和重复项目展示。历史输入可用已成功发布的固定样本验证，真实发布写入由 I5 接通。

### Acceptance criteria

- [ ] 本期与历史均按所属日期北京时间 09:00 比较；不足 168 小时默认排除，恰好满 168 小时及超过窗口可正常入选。
- [ ] 窗口内仅接受上次收录后出现的新正式 Release，或同口径当日新增 Star 至少 2 倍且确有增长；草稿、预发布、缺失值、上次为零不得触发相应例外。
- [ ] 仅最近一次成功发布收录参与比较；失败、预览、重试和更正不新增或重置记录。
- [ ] 再次入选保存例外证据，在正文展示变化并链接上次介绍；筛选仍遵守源顺序、最多 5 个，不足不补榜外项目。
- [ ] 测试覆盖首次、窗口内无变化、正式版本例外、Star 倍增、缺失值、零基数、168 小时边界与实际发布时间偏移；断言能识别按实际发布时间计时等错误实现。

## I4 · 上游失败后安全恢复，复用同一期快照与成功分析

User stories covered：US-2、US-3、US-4。依据：规格 §2、§5–§7。

### What to build

让串行流程能从持久化阶段工件恢复，内部可追踪到具体失败候选和调用消耗。失败后下游不消费半成品；可恢复失败在同一份有效快照上重跑，不重复计费已成功分析。

### Acceptance criteria

- [ ] 同一期固定第一份校验通过的完整榜单快照；重跑不替换候选、顺序、热度或采集时间，尚无有效快照才重新采集。
- [ ] 成功分析按期次及快照身份复用，模型或 schema 不兼容的缓存不得静默复用；恢复后预览与固定工件一致。
- [ ] 记录各阶段待执行、执行中、成功、失败等约定状态及候选决策、失败原因、尝试次数和调用消耗；不新增公开后台，不将内部记录写入正文。
- [ ] 上游无有效产物时下游停止；单候选不可可靠分析可继续，全部失败或整体未完成保持失败，不把阶段失败写成正常空日报。
- [ ] 每期最多额外重试 2 次，预算检查和已有付费预留在恢复后仍有效；进程中断、重复启动不重置计数或预算。
- [ ] 故障注入验证无快照重抓、有快照复用、成功分析复用、损坏工件、阶段中断及重复执行，断言外部调用次数和最终页面数据。

## I5 · 完整发布公共日报、归档与成功收录历史

User stories covered：US-1、US-2、US-3。依据：规格 §1、§5–§7。

### What to build

把校验通过的日报完整发布到公共静态网站，首页、按日期倒序的归档和每期独立页面一致可读；发布成功后维护与公开期次一致的收录历史。生产自动调度在 I6 启用。

### Acceptance criteria

- [ ] 免登录访问手机和桌面页面，清晰显示日报日期、真实发布时间、快照采集时间、来源、覆盖范围、数量和分析；历史持续归档不自动清理。
- [ ] 只发布完整校验通过的期次；发布失败不破坏旧首页、旧期次或成功收录历史，正常零项目页面显示筛选说明。
- [ ] 每日地址唯一，重复发布请求幂等且不改写首次真实发布时间；记录可见发布完成的时间，不把开始上传时间当作成功时间。
- [ ] 发布与成功历史有一致的提交或可恢复协议，覆盖上传成功但回执丢失、历史提交中断等情况；失败重试不产生重复收录。
- [ ] 在写入首页和历史前校验期次及北京时间截止点；过期任务、迟到回调及旧任务不得补发或覆盖较新期次。
- [ ] 选择并验证预算内托管方案，保存部署环境实测；固定样本集成测试贯通解析、校验、筛选、渲染及发布产物检查，故障注入覆盖发布中断和重复执行。

## I6 · 自动定时运行，到 09:00 放弃未发布期次并展示缺刊

User stories covered：US-1、US-2、US-4。依据：规格 §5、§7。

### What to build

启用提前启动的每日自动流程，贯通预算检查、有限重试、生成和完整发布。首页无需依赖任务成功写入状态，也能在北京时间 09:00 判断当期缺刊。

### Acceptance criteria

- [ ] 验证调度服务的时区、延迟和限额，以 09:00 硬截止点反推启动安排；真实环境记录触发到发布的耗时，不把 PRD 的 UTC 0:00 当作不可改变的选型。
- [ ] 每期包含初次尝试及最多额外 2 次重试，所有生成、校验和发布必须赶在截止点前完成；到点取消后续调用、重试及发布，迟到任务仍被发布侧拒绝。
- [ ] 次日仅创建新一期，不补发昨日；同日重复触发或重叠运行不产生两份快照、重复付费预留或重复期刊。
- [ ] 首页根据北京时间、最新一期日期和实际发布时间独立判断缺刊；任务完全未启动、执行失败和发布失败均显示“今日日报生成失败”，保留上一期真实日期。
- [ ] 首次无日报显示“尚未发布”，到点后同时说明失败；浏览器跨过截止点或重新访问时状态正确，历史页面不受当日缺刊影响。
- [ ] 预算耗尽时停止新增付费调用，可信的预算状态可显示“当月生成额度已用尽”；旧页面保持可读，下月额度恢复后继续新一期调度。
- [ ] 使用可控时钟覆盖截止前成功重试、截止时未完成、跨日、任务未启动、发布失败、预算耗尽和旧任务迟到；保留真实环境调度验证证据，不以模拟测试代替上线验证。

## I7 · 维护者沿原地址更正事实，保留发布时间与收录窗口

User stories covered：US-5。依据：规格 §5–§6。

### What to build

提供维护者使用的受控纠错流程，将事实更正反映到原期次和引用它的首页。无需每日人工审核，不新增用户生成入口或审核后台。

### Acceptance criteria

- [ ] 更正保留期次日期、原 URL、原发布时间及选题，页面显示更正时间和说明；不允许借纠错新增或替换项目。
- [ ] 修订后的 JSON 与静态页面重新经过字段、来源和指标一致性校验，完整替换失败时旧版仍可访问。
- [ ] 更正不新增期刊、不新增或重置收录事件；保留原收录快照与热度比较依据，必要的历史数据事实修复有明确记录。
- [ ] 更正历史期次不回滚较新首页；更正最新一期时首页与独立页面一致，未启动日报生成流程。
- [ ] 验证原地址、时间、变化说明、失败回滚、去重窗口不变及较新首页保护，记录实际维护操作方式。

## I8 · 发起人验收确认（原连续试读门槛已取消）

User stories covered：US-1、US-5。依据：规格 §9。

2026-11-10 决定：发起人明确取消以下历史七期试读要求，确认已阅读且满意。原清单保留为历史，不补造记录；月度预算与技术验证继续按现行规格执行。

### What to build

在完整自动流程上线后，记录连续 7 期真实阅读和运行结果，由发起人判定价值与阅读体验。此任务包含人工参与及真实时间等待，不可由 AFK Agent 自行宣布通过。

### Acceptance criteria

- [ ] 逐期记录日期、实际发布时间、阅读耗时、有价值项目及理由、事实问题、失败或缺刊和费用；无有价值项目如实记录。
- [ ] 至少 5 期同时满足 10 分钟内读完，以及至少 1 个项目使读者认为了解其关注价值；未知原因不得为达标强行解释。
